# 项目状态与验证边界

## 这份仓库是什么

这是《世界征服者4 / World Conqueror 4》1914 场景移植研究中筛出的自写工具。它能够独立进行已知 BTL 格式转换、将领 ID 冲突分析、特定 ARM64 地图切换补丁及 APK 差分检查。

**它没有包含最新内部测试 APK 的完整组装链，也不是可安装的成品 Mod。** 原地图、人物、图集、原生库和签名文件没有随仓库公开。能运行这些工具不等于能够从零复现历史内部包。

## 历史进度（2026-09-22 记录）

最新本地实施状态记载：

- 使用 API 30 arm64 Android 模拟器，1914 场景可显示、可进入一个测试国家的第 1 回合；原 1939 场景也做过进入检查。
- 地图切换使用了特定目标原生库的最小适配，没有把来源引擎整库移入目标包。
- 将领头像与部分国旗问题有后续修复；战场国旗有静态组装记录。
- 已操作过 5 档速度及 AI 快进按钮，但没有同场景原版计时对照，不能据此认定加速回归通过。
- 快速测试版用于隔离测试，未覆盖正式安装或正式存档。

仍未完成的项目包括：多类国家各 20 回合、胜负结算、完整边界与海陆通行、场景保存和重启读取、原地图与新地图的移动/战斗/过回合加速对照，以及实体 Android 设备验证。退出场景后的部分地图预览状态仍异常，来源缺失的 `flag_274` 未被猜测补造。来源中两个未解析将领字段值 `12940`、`29422` 也未被随意清零或替代。

这些是历史记录中的进度，不是本次重新在模拟器或手机上运行的结果。

## 为什么没有收录旧的一键合并与发布脚本

- 初期合并方案曾给导入兵种继承不相关的目标兵种字段，出现已确认的模板污染；对应候选被撤回。
- 若干后续脚本依赖特定的中间 APK、派生映射表、图集与人工核对结果。只复制脚本而不说明这些依赖，会把不闭合的链条误写成完整构建流程。
- 旧 `final_gate.py` 和早期门槛 JSON 固定写入过“没有模拟器”等环境判断；后来的实施记录已经覆盖这些判断，不能再拿它们代表最终进度。
- 签名密钥、原 APK、DEX、反编译游戏代码、原始地图/图片和完整备份均不纳入公开源码。

因此这里只保留能够定义独立输入、输出与静态检查范围的四个工具。要继续完成整张地图，仍须处理数据与运行语义的依赖闭包，并重新建立可复现的组装流程。

## 本次整理做了什么

- 保留 BTL 48 字节军队记录扩展为 64 字节时的字节保真与逆向还原检查。
- 给场景 ID 审计及转换/补丁工具补充显式输入输出路径，去掉个人绝对路径。
- 拒绝用优化模式 `python -O` 绕过研究工具依赖的断言检查；原生补丁增加 ELF 架构和最小长度验证。
- APK 差分工具改为可导入、只读的命令行工具，修正原生库在变化分类中未归为代码的问题；保留历史保护规则的具体适用范围。
- 使用完全合成的 BTL、ELF 与 ZIP 数据运行测试，不使用真实游戏资源或签名密钥。

本次没有生成、签名、安装或启动真实 APK，也没有运行模拟器或接触正式存档。合成测试不能证明游戏玩法、保存流程、全部国家或超级加速兼容。
